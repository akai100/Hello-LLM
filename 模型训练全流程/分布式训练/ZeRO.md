
Zero（ZeRO，全称 Zero Redundancy Optimizer）是由微软 DeepSpeed 团队提出的一套用于大规模模型分布式训练的显存优化技术。
其核心思想是：通过将模型状态（参数、梯度、优化器状态）在多个 GPU 之间进行分片（sharding），消除传统数据并行中各 GPU 存
储完整副本所造成的冗余，从而显著降低单卡显存占用，使得训练超大模型成为可能。

## ZeRO 三个阶段

### ZeRO-1：仅分片优化器状态

+ 分片内容：只将 优化器状态（如 Adam 的 momentum、variance）按 GPU 分片

+ 参数 & 梯度：每个 GPU 仍保存完整的 FP16 参数和梯度

+ 通信方式：

  + 前向/反向：与 DDP 相同
 
  + 更新时：各 GPU 用自己的分片优化器状态更新本地参数 → AllReduce 同步参数

+ 显存节省：最多减少 约 4 倍（取决于优化器状态占比）

+ 优点：实现简单、通信开销低

+ 适用场景：模型参数不大，但优化器状态占显存主导（如使用 Adam）

### ZeRO-2：分片优化器状态 + 梯度

+ 分片内容：优化器状态 + 梯度

+ 参数：仍完整保存在每个 GPU

+ 通信方式：

  + 反向传播后，梯度不再 AllReduce，而是通过 Reduce-Scatter 聚合并分片
 
  + 每个 GPU 只保留自己负责的梯度分片
 
  + 用该梯度分片 + 优化器状态分片 → 更新对应参数分片 → 再 AllGather 同步完整参数

+ 显存节省：比 ZeRO-1 更多，最多减少 8 倍

+ 通信开销：略高于 ZeRO-1（多了 Reduce-Scatter）

+ 适用场景：中等规模模型（如 10B~50B），需进一步节省显存

### ZeRO-3：全模型状态分片（参数 + 梯度 + 优化器状态）

+ 分片内容：全部三部分都分片！

  + 每个 GPU 只持有模型的一小块（如某几层 Transformer）

+ 训练流程（关键创新）：

1. 前向传播：

  + 当前需要某层参数时，通过 AllGather 从其他 GPU 获取完整参数

  + 计算完后立即释放（不长期驻留）

2. 反向传播：

  + 类似地，需要某层参数时再 AllGather

  + 计算梯度后，通过 Reduce-Scatter 将梯度归还给负责该分片的 GPU

3. 优化器更新：

  + 各 GPU 并行更新自己负责的参数分片

+ 显存节省：接近线性下降（N 卡 → 显存 ≈ 1/N）

  +  理论上可训练无限大模型（受限于通信带宽和计算时间）

+ 通信开销：最高，因频繁 AllGather / Reduce-Scatter

  + 但可通过 通信-计算重叠（overlap）、参数预取（prefetching） 优化

+ 高级功能：

  + 支持 ZeRO-Infinity：将不活跃的参数卸载（offload）到 CPU 内存或 NVMe 硬盘

  + 支持混合精度（FP16/BF16）

+ 适用场景：

  + 超大模型（如 LLaMA-2 70B、GPT-3、千亿参数模型）

  + 多节点、高带宽集群（如 InfiniBand 网络）
